# Native wrapper and supervisor

`createLaunchSupervisor(SupervisorOptions)` provides concrete `LaunchEffects` for `startLaunch(store, journal, supervisor.effects)`. It returns a `completion` promise and `stop(reason)` / `reconcile()` methods. It does not claim backend acceptance or release capacity: pass only its positive exact stop evidence to `recordExitAndRelease`. A held outcome retains the existing launch identity and reservation; retries never spawn a replacement.

Options bind the durable journal/store, expected capability key/evidence, current-configuration callback, actual harness adapter and canonical absolute executable, prompt, explicit approved environment/allowlist, qualified stop adapter and backend callbacks. `markStarting` uses the current run grant; `authorize(receipt)` uses the separate machine/project supervisor authority and returns `{launchId,authorized:true,leaseUntil}`; `renew(receipt)` returns `{runId,epoch,leaseUntil}`. `hold(reason)` records uncertainty through the independent supervisor channel. No backend credential is sent to the wrapper or harness. Qualification is checked before starting, before releasing the wrapper and on renewal. Missing/stale/fixture evidence, changed configuration, mismatched adapter version, or absent configured stop adapter blocks managed launch.

The concrete child entry point is `launch-wrapper.js`. It receives its exact executable/argv and approved environment through a private IPC channel. The wrapper obtains its own actual OS boot/PID/start identity and fsyncs a mode-0600 receipt in the existing private launch directory before acknowledging it to the parent. The parent compares the IPC receipt to the durable file and reserved launch. `startLaunch` persists that receipt, requests current backend authorization, fsyncs the authorized journal, then releases only the exact receipt digest. Before that release no harness spawn is attempted. A durable `spawn_attempted` marker precedes the OS spawn effect, so a crash around spawn remains uncertain.

`readNativeBootId` and `nativeProcessIdentity` read Linux `/proc` boot UUID/start ticks or macOS `sysctl kern.boottime` plus targeted `ps` start/group identity. Unsupported/denied inspection never falls back to PID existence or an inferred clock-based boot identity. macOS `ps` has second-level start precision: this provider is an observation primitive, not a stand-alone PID-reuse or containment qualification. The owned wrapper's connected IPC identity and exact receipt further bind authorization; a production stop adapter still needs the selected host's demonstrated containment/identity guarantees. Windows currently fails closed.

Environment construction copies only explicitly configured names/values, never `process.env`. Supervisor, approver/human, artifact-verifier, project-agent and known provider credential names, dynamic-loader overrides and Git configuration overrides are rejected even if listed. The run-scoped credential may be explicitly supplied where required. `HOME`, `PATH` and other execution values must be deliberately selected. macOS may synthesize its noncredential CoreFoundation encoding marker. Environment filtering does not isolate readable credential files, helpers, agent sockets or native tools. Those boundaries remain separate mandatory real qualification checks; sign-in and a cleaned environment are insufficient.

The parent renews every 20 seconds by default. Confirmed exact renewal is forwarded over the receipt-bound IPC channel. Both parent and wrapper use independent monotonic watchdogs: 60 seconds without confirmation triggers stopping, and the default run timeout is 30 minutes. Revocation/configuration change and IPC loss trigger stopping earlier. Timings are configurable with bounded values for approved run policy and deterministic fixtures. A hung renew does not block the independent watchdog. The wrapper requires no supervisor/backend credential to enforce its local deadline.

Stopping first sends TERM and arms escalation before awaiting evidence I/O. The wrapper then attempts KILL of its verified own POSIX process group after the configured grace period (default five seconds). Outcome fsync failure cannot postpone those signals. Escalation stays alive after the direct child exits, including when a grandchild ignores TERM. Unexpected wrapper exit also asks the live parent’s qualified stop adapter to stop the recorded containment. These are best-effort safety actions. Process-group absence, direct-child exit, successful signal delivery and no `ps` matches never prove the entire descendant tree ended. Descendants can escape an ordinary group unless the selected host prevents it.

`QualifiedStopAdapter` binds the expected capability key and implements `stop(receipt,reason,observation)` and `observe(receipt,observation)`. Only exact, positive `StopEvidence` from the selected tested containment is accepted. There is no default full-tree adapter that pretends an ordinary process group is a sandbox. If proof is unavailable, stop fails, the wrapper/IPC is lost, or restart cannot recover supervision, the result is held and requires positive reconciliation. Root-child exit alone always stays held. A crash-left journal is never an invitation to respawn.

A durable `never_started` wrapper outcome before any receipt, together with the owned wrapper's observed exit and completed identity subprocesses, can provide `proven_never_started`. Once a wrapper receipt exists, the conservative generic contract does not accept that evidence kind. The qualified adapter may instead demonstrate exact `observed_tree_exit` for a controlled never-released wrapper, including its awaited subprocesses, or retain the hold. Missing files or an unresponsive wrapper do not prove it never started.

The tests launch only disposable Node fixtures, with synthetic authority records that are never saved as host qualification. The restricted macOS run exercises guard/env checks and actual denied-identity never-started handling; native-path cases are explicitly skipped. A narrowly escalated local run permits read-only boot/process inspection and exercises receipt-before-authorization, exact environment, denied release, parent and independent wrapper watchdogs, and IPC loss where the root exits on TERM but a descendant ignores it. Stopped fixture heartbeats establish those fixture outcomes only. They do not certify actual Codex/Antigravity tool isolation, native containment, a real backend, or two-machine execution.
