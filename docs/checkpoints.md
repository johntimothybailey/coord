# Checkpoints, resume and review artifacts

These helpers implement local Git/environment effects. Backend preparation, independent remote evidence, ready acceptance, admission and PR acceptance are separate authenticated operations. A returned local artifact is not proof of backend authority or a qualified host.

`captureCheckpoint(CaptureOptions)` returns `PreparedCheckpoint`, extending the shared `CheckpointManifest` with `createdAt`, `progressRevision`, `policyDigest`, `manifestDigest` and `reusedCommit`. Supply a selected remote `{name,url}`, immutable checkpoint/run identity, exact execution base `{sha,revision,remoteRef}`, structured progress and revision, stable creation timestamp, repository-approved commit message and explicit `CapturePolicy`. `readAuthority(phase)` must query authenticated current backend state and return the exact identity/base/progress hash/revision/policy digest; it must reject expired/revoked authority. `quietBoundary()` obtains the real adapter checkpoint boundary. Neither callback may substitute local model claims for backend checks.

Capture serializes each worktree with an exclusive lock inside its actual Git directory. It pins source HEAD, fetches the selected remote base into a unique temporary ref, and verifies the exact execution base is both remote-reachable and incorporated by source HEAD. A new upstream tip never changes that parent. The private temporary index pathname does not exist before `read-tree <pinned-source-head>`. Selection includes tracked working files/deletions and staged additions, plus only explicitly allowed untracked files. Exclusions are exact explained paths; missing required assets block capture. Complete before/after manifests include type/mode/blob identity, source index identity, timestamps and effective attributes. Candidate entries must equal the complete intended manifest. Repeated instability fails after three attempts.

The entire final tree and actual new commit metadata are screened, including unchanged inherited tree files. Screening uses selected literal canaries plus a small declared built-in key/file detector; it makes no universal secret-detection claim. `.coord-local` is reserved machine-local credential/receipt data and requires exclusion if it would otherwise be selected. Source index, branch, files and history are preserved. Git object creation and temporary refs are expected local effects. Symlinks must remain within the repository; special files, submodules, LFS/clean filters, explicit text/EOL conversion, nonfalse `core.autocrlf`, encoded worktrees and oversized files fail explicitly. This initial limitation avoids executing repository filters or publishing a falsely normalized tree.

New snapshots have exactly the verified execution-base parent. Their full intended message, fixed author/date and checkpoint/progress/manifest identity regenerate to the exact same commit hash on validation. A forged same-tree commit, secret message, replacement ref or mismatched metadata cannot pass. Replacement objects are disabled for every Git invocation; legacy grafts and shallow source provenance block capture. If the tree equals the remote-present base tree, capture reuses that existing commit and records `reusedCommit: true`; `remoteParent` still records the execution baseline, while actual read-back parents describe the reused commit's true parentage.

`publishCheckpoint(options, manifest)` publishes only the exact audited snapshot. `verifyRemoteCheckpoint(options, manifest, ref?)` fetches and returns `RemoteCheckpointReadback`: commit/tree, actual `parents`, single `parent` or null, exact ref, manifest/progress/policy hashes and verification time. Add a persisted evidence reference when submitting supervisor read-back to the backend. The immutable create uses `--force-with-lease=<exact-ref>:` with an empty expected old value. This is a create-only compare-and-swap: it cannot update any existing ref, including an ancestor-compatible one. It preserves the specification's no-history-rewrite intent while closing the race between ref lookup and push. Matching same-ID refs reconcile; different content blocks. Explicit `--no-follow-tags`, `push.followTags=false` and remote mirror suppression prevent incidental tag/all-ref publication. No general force update exists.

`createResumeWorktree(ResumeWorktreeOptions)` requires a selected ready checkpoint, admitted destination identity/project ID, canonical worktree root/common Git directory, fresh environment preflight, `assertReady()` and `assertAdmission()` callbacks. It fetches exact code, checks the environment before admission validation and again before allocation, creates a new `coord/tasks/<task>/e<epoch>/<run>` branch, verifies common Git/remote/head/tree, and writes mode-0600 `.coord-local/run.json` under a mode-0700 directory. The receipt matches `resolveWorkspace` inheritance. Existing paths/branches are never reset; post-allocation failures retain an inspectable orphan. It returns source HEAD provenance and the original execution baseline. It does not run setup or a model. The caller must preflight before reserving capacity and release only a provably unused reservation on failure.

`checkEnvironment(requirements, mode, options)` resolves only declared keys from exported environment, explicit files and approved providers. Exported values, including empty values, take precedence. Reports contain names, source identifiers, presence/type failures and nonsecret digests; values never leave the function. Required production keys do not affect a mode that does not declare them. Supported env files have simple assignments and literal quotes; expansion, multiline/escaped syntax and provider failures block explicitly. `requireEnvironment(report)` raises `BLOCKED_ENV` for missing or invalid keys. `inspectSetup(repo, commands)` records lockfile hashes, actual Node/Git/selected package-manager versions and supported frozen install commands; it performs no install or repository script execution. Corepack network installation is disabled during version probes. Unsupported flags or missing corresponding lockfiles block setup inspection.

`prepareReviewArtifact` reuses `captureCheckpoint`; an already ready audited checkpoint can be reused directly. `publishReview(PublishReviewOptions)` accepts an independent stable publication ID, selected repository/target, exact final-commit/tree/current-target verification, required command policy, environment digest, current authority/conflict/coverage/native-permission preflight, and a host adapter limited to `find/create/read`. It publishes the same safe snapshot under `coord/reviews/<task>/e<epoch>/<publication>`, never the task's private ancestry. Verification on source HEAD alone is rejected. The result is `verified_external`, with actual branch read-back and exact repository/head/base PR data; backend acceptance and process/capacity release remain separate.

PR creation records a durable local journal before calling the host. The common Git directory and journal directory entries are fsynced; writes use synced mode-0600 temporary files and atomic rename. Matching records across all host PR states reconcile lost responses. Closed/stale/ambiguous records and an unresolved `create_pending` journal block blind duplicate creation. Concurrent attempts use an exclusive per-publication lock. A crash-left lock requires explicit recovery after proving no publisher remains; it is never guessed stale. A moving target requires integration/base-sensitive verification, and leaves any external artifact unaccepted. Local journals do not promise external exactly-once API behavior.

Tests use real disposable source/bare/destination Git repositories and fake host adapters. They cover T6–T9, T14–T15 and T18, including committed-then-deleted secrets, tag metadata, replacement refs, an upstream advance in task/unrelated files, source-offline fresh reconstruction, existing-directory preservation, write-and-revert races, lost push/PR responses and immutable-ref collisions. Source-offline directories on one machine are a rehearsal, not two-machine A6. Real backend/supervisor qualification, both live harness continuation directions, native human unlock/credential/merge/deploy restrictions and a selected Git host remain required external evidence.
